# Token：颜色、字样、间距

来源：`raw/design-system/tokens.json` / `tokens.css`，终端主题文件 `apps/tui/theme.json`（shadcn `cssVars.dark`）。只有一个主题：深色 Terminal。

## 色深与回退原则

- 真彩（`COLORTERM=truecolor`）：宿主把主题 token“钉色”为下表的十六进制值。
- 256 色：取最接近的 xterm-256 色；半透明 token 用下表给出的“混合后实色”。
- 16 色：用下表“16 色”一列；面板不铺底色，靠边框和间距分层。
- 单色（`NO_COLOR` 或 `COFFEE_COLORS=mono`）：只用属性：**粗体**、**暗淡**、**反显**、**下划线**、**删除线**。
- `acc` 填充上的 `ink` 字（主按钮、状态栏模式块）实测四种色深都可读（`COFFEE_COLORS` 强制）：真彩 `#1a140d` on `#f0b45a`；256 色 233 on 215；16 色为黄色反显（字为终端底色）；单色为反显 + 粗体。nsh 把 `ink` 画成终端默认前景，是宿主钉色把它换回 `ink`（`crates/coffee-host/src/palette.rs`）。
- **任何状态都必须同时有字形和属性**，颜色只是第三重提示：选中 = `▶` / `▐▌` / `◉` / 粗框 + 粗体或反显；错误 = `✗` / `!` + 粗体；成功 = `✓`；禁用 = 暗淡 + 删除线或说明文字；开关 = `■ 开` / `□ 关`；勾选 = `[✓]` / `[ ]`。

### 终端载体（carrier）

nsh 0.6.1 在终端里不画颜色值，只画 ANSI 含义：饱和色变成所在色相带的强调色（`Yellow` 琥珀、`Green` 薄荷、`Red` 珊瑚、`Cyan`、`Blue`、`Magenta`），中性色变成默认前景或“默认前景 + DIM”，底色只在 3 行以下的盒子上画（饱和不透明色画准确 RGB / 256 色索引，中性色画标准灰）。九种棕色在它那里都是“暗淡”。所以每个 token 经由一个能穿过这套映射的**载体**送到终端，`coffee-host` 的钉色（`crates/coffee-host/src/palette.rs`）再在每种色深下换回 token。载体表在 `apps/tui/src/ui/theme.rs`（`INKS`、`FILLS`），钉色从它和 `theme.json` 构建自己，两边只有这一处约定。

- **文字 / 线条**：一个通道（nsh 给出的 ANSI 含义）+ 可选的**标记**——斜体属性（设计里从不用斜体）。钉色去掉标记，所以终端里不会出现斜体；单色下颜色全无，但属性还在，带标记的就加暗淡。
- **底色**：一个饱和、正好落在 xterm 色立方上的 `carrier-*` 颜色，以 94% 不透明度画（`theme::CARRIER_OPACITY`：足以让 nsh 原样画出它，又不会被当作文字的底或主按钮的填充），nsh 原样画出（真彩是 RGB，256 色是该立方格），钉色换回 token。

- 纯 `Blue` 不作载体：nsh 用它画自己的焦点标记（获得焦点的输入框整行反显的蓝带等），钉色把它换成 `acc`，把输入框的蓝色反显带换成 `selection` 底色带上的正常文字（设计的焦点是输入框的 `acc` 粗框）。
- 单色下所有带标记的色调只能一并变暗：`success-border` / `destructive-border` 的括号与边框因此是暗淡而不是规格写的“正常”（括号里的文字仍是正常亮度）。
- 16 色下 `mute` 保持 nsh 的“默认前景 + DIM”，而不是亮黑 90：两者都读作次级文字，DIM 在浅色终端主题下更可靠。
- 只能经 `ui::label` / `ui::strong` / `ui::toned` 或 `Tone` / `Fill` 的组件着色：单独的 `Tone::color()` 不带标记，会被钉色读成另一个 token。
