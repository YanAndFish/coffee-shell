# ROAST/TTY 终端设计规格

这组文档把 `raw/` 里的 HTML 设计稿（1280×800 px 的“终端窗口”）和 ROAST/TTY 设计系统换算成**字符格**上的规格。第二阶段的 TUI（Rust + nsh）只照这里实现：所有字符串、数字和按键都取自源稿；源稿缺少、而本阶段决策又需要的内容，一律标 `（新增）`，并在 [copy.md](copy.md) 里集中列出。

`raw/` 是只读的源文件，不要修改。本文档与 `raw/` 冲突时，以本文档为准，冲突点都列在下面的“与设计稿的差异”里。

## 怎么读这些规格

1. 先读本页的“格子换算”和“示意图记号”。
2. 写组件前读 [components.md](components.md) 与 [tokens.md](tokens.md)；写页面前读对应的 `screens/0x-*.md`，它给出 160×50 的完整示意、区域格数、逐字文案、焦点顺序、所有状态和小尺寸布局。
3. 按键以 [keymap.md](keymap.md) 为准（它已经消解了源稿 `HINTS`、`HELP` 与按键处理函数之间的不一致）；文案以 [copy.md](copy.md) 为准；数字规则以 [data.md](data.md) 为准（金额全部由服务端计算，TUI 只显示）。

## 格子换算

- **1 格 = 8×16 px**。设计稿 1280×800 px 正好是 **160 列 × 50 行**，这也是 XL 断点的基准尺寸。nsh TUI 的默认 `pointsPerCell` 同为 8×16。
- 横向：`列数 = px ÷ 8`；纵向：`行数 = px ÷ 16`；四舍五入，**恰好 .5 时向下取**（宁少一格）。
- 例外（以免照公式算出不合理的高度）：
  - 一切单行控件（按钮、筛选项、Chip、Stepper、Toggle、导航标签、状态栏）**高 1 行**，不论源稿是 28 px 还是 50 px；多出来的 px 变成上下的空行。
  - 有边框的输入框、凹陷信息块、卡片、对话框：上下边框各占 1 行，所以单行输入框 = **3 行**。
  - 纵向间距 ≤ 8 px 记 0 行，9–24 px 记 1 行，25–40 px 记 2 行。
  - 两行文字的数据行（商品列表、购物车）固定 **3 行**（2 行文字 + 1 行间隔）；订单行 2 行（文字 + 分隔）。
- 换算只是起点，**每个画面规格里写出的格数是最终值**。没有字号、圆角、阴影和亚格间距：层级靠粗体 / 暗淡 / 反显、边框、字形和颜色。
- **显示宽度**：Unicode East Asian Width 为 W 或 F 的字符（中文、全角标点、`「」`）占 2 格；其余一律 1 格，**包括“模糊宽度”字符**（制表符 `─│╭`、`·`、`●○`、`→`、`×`、`¥`、`…`、`▉`）。这与 Rust `unicode-width` 的默认（非 CJK）口径一致。把“模糊宽度按宽字符显示”的终端设置视为不支持（见 [responsive.md](responsive.md#字符宽度)）。
- 省略号 `…` 占 1 格；截断时不得把一个宽字符劈成两半。

## 示意图记号

示意图里的字符就是终端里要画的字符，只有下面两种记号例外：

| 记号         | 实际画法                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `‹a›`        | **键帽 Kbd**：`‹` `›` 两格画成空格，与中间的键名一起铺 `kbd-bg` 底色、键名加粗；16 色与单色为反显。宽度不变（3 格起）。 |
| （背景变暗） | 对话框打开时，背后的所有内容加 `dim` 属性；示意图无法表现，按原样画出。                                                 |

其余是真实字形：

| 字形        | 含义                                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------------------- |
| `▐ 文本 ▌`  | 实心“药丸”：主按钮、选中的分段 Chip、实心 Tag、状态栏模式块。两端半块字符用填充色作前景，中间填充色作底、`ink` 粗体字 |
| `[ 文本 ]`  | 次级按钮；无内边距的 `[文本]` 是未选中的 Chip 或描边 Tag                                                              |
| `╭─╮ │ ╰─╯` | 普通面板 / 输入框（`line` 色）                                                                                        |
| `┏━┓ ┃ ┗━┛` | **焦点或选中**的框（`acc` 色）：聚焦的输入框、当前地址卡、头像                                                        |
| `╔═╗ ║ ╚═╝` | 对话框                                                                                                                |
| `╭╌╮ ╎`     | 虚线框：“新增”占位卡                                                                                                  |
| `╌╌╌`       | 虚线分隔（合计前）                                                                                                    |
| `┈┈┈`       | 点线：键值引导线、订单行分隔                                                                                          |
| `▶`         | 当前行 / 当前卡（游标）                                                                                               |
| `›`         | 输入提示符；SKU 焦点组标记                                                                                            |
| `▉▉▉░░░`    | 分段计量条 / 进度条                                                                                                   |
| `━━━───`    | 细进度条（免运费进度）；顶栏下边线里的 `━` 是当前导航标签的下划线                                                     |
| `⣠⠴⠚⠦⣄`     | 盲文点阵画的风味雷达                                                                                                  |

示意图的列宽与行数都用脚本校验过（中文按 2 格计）：160×50 的示意每行恰好 160 列、共 50 行；80×24 的示意恰好 80×24。示意代码块上方的 `<!-- mock 宽x高 -->` 注释就是它的尺寸，修改示意时要保持一致（`pnpm check:mocks` 即 `scripts/check-mocks.py` 逐行校验，CI 也跑）；紧跟的 `<!-- prettier-ignore -->` 防止格式化器删掉行尾空格（行尾空格是示意宽度的一部分），不要删。

## 全局框架

下表是 XL（160×50）的行分配；其他断点见 [responsive.md](responsive.md)。

| 行   | 区域         | 说明                                                                                                                              |
| ---- | ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 0    | 系统行       | 替代设计稿的窗口标题栏：左 `roast@tty: ~/shop — 160×50`（实时尺寸），中间常驻 `! 演示环境 · 不是真实商店`，右 SSH 公钥状态 + 时钟 |
| 1–4  | 顶栏         | 字标、导航、搜索框、账户（登录页没有顶栏，这 4 行归内容区）；第 4 行是下边线                                                      |
| 5    | 内容区上边距 | 空行                                                                                                                              |
| 6–47 | 内容区       | 面板区；左右各留 2 列边距（列 0–1、158–159）                                                                                      |
| 48   | 内容区下边距 | 空行；Toast 可以盖住 44–47 行                                                                                                     |
| 49   | 状态栏       | 模式块 + 本页快捷键 + 鼠标 / 购物车金额 / 帮助                                                                                    |

nsh 自带的 Toast 和搜索占用最底行，会与状态栏冲突，所以 Toast 由应用自己画（见 [components.md](components.md#toast)）。

## 与设计稿的差异

| #   | 设计稿                                                               | 终端实现                                                                                                                                                                                   |
| --- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | 1280×800 px 的窗口，字号、圆角、阴影、半透明                         | 160×50 格；尺寸取整到格；没有字号 / 圆角 / 阴影 / 亚格间距；层级用粗体、暗淡、反显、边框、字形与颜色表达                                                                                   |
| D2  | 34 px 假窗口标题栏，显示“键盘已连接 / 单击窗口以使用键盘”            | 终端本身就是窗口：标题栏换成 1 行系统行；键盘状态改为 SSH 公钥状态 `● 公钥已识别` / `○ 未提供公钥`（新增）                                                                                 |
| D3  | 颜色是写死的十六进制                                                 | 颜色来自主题 token（`apps/tui/theme.json`），真彩终端显示准确色值；16 色与单色下必须同样可读——**状态永远是“字形 + 属性”，不只靠颜色**（见 [tokens.md](tokens.md)）                         |
| D4  | 登录是演示：预填 `linxiao@roast.tty`，点击“注册新账号”只弹 Toast     | 真实账号，由后端管理：只有**用户名 + 密码**，没有邮箱、没有验证；注册是真实流程，同样两个字段。字段标签“账号 / 邮箱”改为“用户名”                                                           |
| D5  | “在此终端保持登录 7 天”                                              | “记住我 30 天”：把账号绑定到本次连接的 SSH 公钥，30 天内用同一公钥连接自动登录；连接没有公钥时该项禁用并显示原因                                                                           |
| D6  | 访客可加购，结算前登录（脚本已如此）                                 | 同左；登录后访客购物车**合并**进账号购物车；因结算而去登录的，登录后回到购物车                                                                                                             |
| D7  | 演示：结算后直接出回执                                               | 不接支付，“下单即完成”；回执上明示 `! 演示订单 · 没有真实扣款，也不会发货`（新增）                                                                                                         |
| D8  | 无                                                                   | 每个画面常驻 `! 演示环境 · 不是真实商店`（系统行）；登录 / 注册卡片上另有 `! 演示环境 · 请勿使用真实密码`                                                                                  |
| D9  | 计价在前端脚本里                                                     | 计价、优惠、运费、库存校验、订单号、ETA 全部在服务端；规则与脚本一致（见 [data.md](data.md)）                                                                                              |
| D10 | 固定 1280×800                                                        | 响应式断点：<80×24 显示“终端太小”；S 80–99 列；M 100–129；L 130–159；XL ≥160（内容最宽 200 列）；少于 32 行时用单行字标、去掉咖啡杯、雷达降级为计量条（见 [responsive.md](responsive.md)） |
| D11 | 大量过渡动画（换页、逐行进场、游标滑动、弹出、计量条缓动、徽标回弹） | nsh 在终端里报告“减少动效”：只保留盘旋字符、进度条前进和蒸汽三帧轮换；其余一律即时（见 [states.md](states.md#动效清单)）                                                                   |
| D12 | 搜索框是 300 px 的常驻输入框                                         | XL/L/M 顶栏仍显示 3 行的搜索框；S 只显示 `‹/› 搜索`，按 `/` 后顶栏第一行变成输入框                                                                                                         |
| D13 | 详情页默认研磨：初始状态是“手冲”，从列表打开是“整豆”                 | 统一为**整豆**（`openDetail` 与“快速加入”的行为）；示意图按此绘制                                                                                                                          |
| D14 | 列表、购物车的游标只是一块滑动的半透明高亮                           | 加 `▶` 字形（购物车原稿没有）+ 选中底色带；单色下为反显                                                                                                                                    |

更多按键层面的不一致见 [keymap.md](keymap.md#源稿冲突与处理)。
